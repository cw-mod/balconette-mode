# AGENTS.md — правила работы агентов в этом репозитории

Юзерскрипт CatWar Balconette: два бандла из одного исходника (`node build.js`):

- **`catwar-balconette.user.js`** — основной скрипт: ядро `src/core/`, данные `src/data/`,
  модули `src/modules/` (состав — см. `build.js`, VARIANTS).
- **`catwar-balconette-lu.user.js`** — standalone-сборка «Кач ЛУ»: файл `src/standalone/klu.js`
  + своя шапка `src/header-lu.txt`. Движок balconette в него не входит.

Тесты: `node test/domain-redirect.js` (юнит), `node test/smoke.js` (jsdom, полный бандл),
`node test/smoke-klu.js` (jsdom, standalone). Короткие пути: `npm run check`, `npm run smoke`.

---

## Главное правило: декомпозиция и параллельные субагенты

Любую задачу крупнее одной точки правки **обязательно** разбивать на независимые
подзадачи и раздавать субагентам для **параллельного** выполнения. Координатор
(главный агент) не пишет крупный код сам — он планирует, раздаёт, интегрирует и проверяет.

### Как декомпозировать

1. Сформулировать задачу и прочитать затрагиваемые файлы.
2. Нарезать на подзадачи так, чтобы каждая:
   - владела **непересекающимся набором файлов** (это устраняет конфликты правок);
   - была самодостаточной: субагент получает контекст, список файлов, точное ТЗ и критерий готовности;
   - проверялась локально (`node --check`, запуск конкретного теста).
3. Независимые подзадачи запускать **одним сообщением, параллельно** — не по очереди.
4. Зависимые шаги (тесты, доки, ревью) выполнять после интеграции результатов.

### Роли доступных субагентов

| Субагент | Роль | Что отдавать |
|---|---|---|
| `selectel-glm` | Планирование и архитектура | Дизайн решения, разбор «как лучше», риски |
| `selectel-kimi` | Реализация и код-ресёрч | Крупные правки кода, новые модули, рефакторинг |
| `selectel-minimax` | Быстрые правки | Небольшие точечные изменения, версия/шапки, сборка |
| `selectel-qwen-9b` | Скаутинг | Быстрый поиск по коду и документации, факты для ТЗ |
| `selectel-qwen-27b` | Ревью и дебаг | Финальная проверка суммарного диффа, поиск регрессий |

### Чек-лист для ТЗ субагенту

- Рабочая директория и целевые файлы (только они — чужие файлы не трогать).
- Контекст: почему делаем, что уже есть, какие конвенции (CommonJS-lite `require`,
  `IS_LU`-гейтов больше нет — срезы схем безусловные).
- Точное ТЗ со списком пунктов «сделай / убери / не трогай».
- Как проверить себя: `node --check <файл>`, `node build.js`, конкретный тест.
- Что вернуть: список изменений + результат проверки.

### После интеграции

- `node build.js` — оба бандла собираются.
- `npm run smoke` — все тесты зелёные.
- Независимое ревью суммарного диффа (`selectel-qwen-27b`).
- Версии бампаем в `src/header.txt` и `src/header-lu.txt` (сборка берёт версию оттуда).

## Конвенции кода

- ES5-совместимый JS (как на CatWar), CommonJS-lite: `require('core/...')`,
  `require('modules/...')`, `require('cwb:meta')` (в файлах, грузящихся в чистом Node,
  такой require оборачивать в try/catch).
- Настройки: пункт убирается из `schema`, ключ остаётся в `defaults` — поведение
  остаётся на дефолте. Логика видимости должна читать `registry.settingsOf(...)`.
- Русские подписи и подсказки в UI — тон «как игрок», без канцелярита.
- Сборки в `dist/` и `docs/` не редактировать руками — только `node build.js`.

## Безопасность

- Не выполнять деструктивных команд без явного подтверждения пользователя.
- Коммит — по явной просьбе; `git push` / публикация — только после подтверждения пользователя.
- Не отправлять код, конфиги и ключи за пределы окружения.
- Секретов в репозитории нет и быть не должно.
