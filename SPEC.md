# CatWar Balconette — техническое задание

Модульный юзерскрипт (Tampermonkey) для CatWar `https://catwar.su/cw3/`.

Документ описывает, **что** делаем, **как устроено ядро** и **как несколько разработчиков
пилят модули параллельно, не мешая друг другу**.

Исходные данные исследования:

- `research/NEW_SITE.md` — разбор нового бандла `cw3.js`: селекторы, socket-события, что сломалось;
- `research/MODS.md` — разбор CW Shed / CW Mod / CatWar UwU: какие фичи были, как сделаны, что переносить;
- `research/site/js_dist_cw3.pretty.js` — разминифицированный бандл игры;
- `research/mods/` — исходники модов;
- `Игровая _ CatWar компактный режим 3 колонки.html` — **эталон компактного режима**;
- `Игровая _ CatWar обычный режим не компактный.html` — **эталон обычного режима**;
- `Игровая _ CatWar обычная без модов не в режиме нюха.html` и
  `Игровая _ CatWar после действия нюха.html` — тоже компакт (название про «без модов/нюха»,
  не про режим интерфейса). Селекторы партии 1 сверены по ним и по двум эталонам (см. §1.1, §1.3).

## 0. Красные линии (нарушать нельзя)

Эти правила выведены из разбора того, как старые моды ломали пользователю чат и игру.

1. **Не трогаем DOM чата.** Запрещено: `display:none` на `#chat_msg`, перенос `#chat_form`
   (`appendChild` / `prepend` в `#tr_chat > td`), подмена или переименование `input#text`,
   клонирование ленты сообщений. Читать чат можно только из Vue (`chat.messages`).
   Отправка — только родным `#msg_send` / Vue API.
2. **Не эмитим сокет-события и вообще ничего не отправляем на сервер.** Скрипт читает и меняет
   отображение. У `move` есть `dynamicToken`, у боя — омографы для нетрастед-событий:
   любая попытка «нажать за игрока» будет отвергнута сервером и выглядит как читерство.
3. **Не открываем вторую вкладку игры.** Сайт детектит мультивкладку (`two tabs`) и рвёт сессию.
   Ни `window.open`, ни `<iframe>` на `/cw3/`, ни фоновых запросов, имитирующих сессию.
4. **Ничего не монтируем внутрь игровых контейнеров.** Свои узлы — только в `#cwb-root`
   в конце `<body>` или через `ctx.mount()`.
5. **Не читаем ширину полосок параметров через `style.width`.** В новом CSS `.bar-fill`
   анимируется `transform: scaleX()`. Значения брать из `parameter.data[name]`.
6. **Не используем `DOMNodeInserted`/`DOMNodeRemoved`**, только `MutationObserver`.
7. **Никакого jQuery, jQuery UI и внешних зависимостей в рантайме.**
8. **Каждый модуль обязан чисто выключаться.** Если что-то нельзя снять — этого делать нельзя.
9. **Не конфликтуем с соседним скриптом пользователя** «досье агентства»
   (`catwar detective/detective-agency-overlay.user.js`): он занимает префикс id `cwa-da-*`
   и ключ `localStorage["cwa-da-ui-v1"]`. Наши префиксы — `cwb-` и `cwb:`.

#### 1.2 Режимы интерфейса: компакт vs обычный

Основной сценарий пользователя — **компакт** (`#app.compact`, `localStorage.cw_compact_game`).
Эталоны: `Игровая _ CatWar компактный режим 3 колонки.html` и
`Игровая _ CatWar обычный режим не компактный.html`.

| Блок | Обычный режим | Компакт (3 колонки) |
|---|---|---|
| `#app` | без класса `compact` | `compact compact-cols-3 …` |
| Чат | `#tr_chat` в `#main_table`: `#chat_msg`, `#chat_form`, `input#text` | тот же `#tr_chat` (часто пустой) + плавающий `#chat_float` с формой |
| Действия | `#tr_actions` в `#main_table` → `#block_deys` | `#tr_actions` в `#compact_actions` → тот же `#block_deys` |
| `#block_deys` | flex-**строка**: `#deys` (73%) + `#deys_mit` (27%) | flex-**колонка**: `#deys`, затем `#deys_mit` |
| Поле | `#tr_field` в `#main_table` | `#tr_field` в `#compact_left` |
| `#cages` / `#cages_div` | под `#main_table > #tr_field` | под `#compact_left > #tr_field` (те же id) |
| Погода | `#tr_tos`, `#tr_sky` в `#main_table` | `#tr_tos` в `#compact_actions`, `#tr_sky` в `#compact_left` |
| Параметры / история | `#tr_info` → `#info_main`: `#parameter`, `#history`, `#family` | те же id, но в `#compact_info` + вкладки `.compact-info-tabs` |
| `#ist` | `<span>` в `#history_block` | тот же путь внутри `#compact_info` |
| Рот | `#tr_mouth` → `#itemList` | `#tr_mouth` в `#compact_actions` |

**Общее для модулей:** id `#mit`, `#akten`, `#deys`, `#cages`, `#parameters_skills_block`,
`#itemList`, `#tos`, `#sky` **есть в обоих режимах**. Модули не должны падать, если узла нет
(страница `/ls`, охота без поля и т.п.) — тихий пропуск через `waitForElement` / проверку Vue.

#### 1.3 `hunt-smell-square` — что делает фича

Перенос из CW Shed (`on_huntText`) и CatWar UwU (`describeHuntingSmell`):

- На странице охоты квадрат `#smell` меняет интенсивность красного в inline-`background-color` по мере приближения к дичи.
- Модуль сравнивает текущий красный канал с предыдущим и показывает подпись: **«Ближе»** (red вырос), **«Дальше»** (red упал), **«Потерян»** (red = 0).
- Опционально — таймер `MM:SS` с момента начала отслеживания запаха.
- Подписи монтируются в `body` (не внутри `#smell`), позиция привязана к `getBoundingClientRect()` квадрата.

### 2.2 Сборка

`build.js` оборачивает каждый файл `src/**/*.js` в CommonJS-lite фабрику:

```js
__def('core/storage', function (require, module, exports) { /* тело файла */ });
```

`require()` ленивый, поэтому порядок файлов в бандле не важен. Точка входа — `core/bootstrap`.
Псевдомодуль `cwb:meta` отдаёт `{ version, moduleIds }`: версия берётся из `@version` в
`src/header.txt`, список id модулей — из имён файлов в `src/modules/`.

**Новый модуль подключается автоматически** — достаточно положить файл в `src/modules/`.
Ничего регистрировать руками в списках не нужно, конфликтов по merge на «списке модулей» нет.

Перед записью в `dist/` build.js прогоняет результат через `new vm.Script(...)` — то есть
сборка падает, если синтаксис битый.

### 2.3 Контракт модуля

```js
module.exports = {
  id: 'grid',                    // обязателен, совпадает с именем файла, kebab-case
  title: 'Сетка на поле',        // подпись в панели
  description: 'Обозначает границы клеток игрового поля.',
  category: 'field',             // field | interface | info | chat | sound | misc
  pages: ['game'],               // где поднимать: game, hunt, chat, pm, profile, settings, '*'
  enabledByDefault: false,
  order: 20,                     // сортировка внутри категории
  warning: 'текст предупреждения', // опционально, красится в панели

  defaults: { color: '#ffffff', width: 1 },   // значения настроек
  schema: [                                    // как рисовать настройки
    { key: 'color', type: 'color', label: 'Цвет линий' },
    { key: 'width', type: 'number', label: 'Толщина, px', min: 1, max: 6, step: 1 },
  ],

  // Чисто-CSS модулю больше ничего не нужно: реестр сам вставит и снимет стиль
  // и пересоберёт его при изменении настроек.
  styles: function (settings, ctx) { return '#cages td.cage { … }'; },

  init: function (ctx) { /* опционально */ },
  destroy: function (ctx) { /* опционально: ctx и так всё уберёт */ },
  onSettings: function (ctx, key, value) { /* опционально, см. ниже */ },
};
```

Типы полей `schema`: `boolean`, `number`, `range` (`min`/`max`/`step`), `text`, `color`,
`select` (`options: [{value,label}]`), `textarea`. У любого поля можно задать `hint`.

**Поведение при смене настройки:** реестр всегда пересобирает `styles()`. Дальше —
если у модуля есть `onSettings`, зовётся он; если нет, но есть `init` — модуль
перезапускается целиком (`destroy` + `init`). Это по умолчанию безопасно.

### 2.4 Контекст `ctx`

Всё, что создано через `ctx`, снимается автоматически при выключении модуля.
Ручной `destroy()` нужен только для того, что `ctx` не покрывает.

| Метод | Что делает |
|---|---|
| `ctx.settings.get(key)` / `.all()` / `.set(key, v)` | настройки модуля |
| `ctx.injectStyle(css, suffix?)` / `ctx.removeStyle(suffix?)` | `<style id="cwb-style-<id>">` |
| `ctx.refreshStyles()` | пересобрать `styles(settings)` |
| `ctx.on(target, type, fn, opts)` | `addEventListener` с авто-снятием |
| `ctx.observe(target, cb, opts)` | `MutationObserver` с авто-отключением |
| `ctx.watch(path, cb, opts)` | Vue `$watch` с авто-отпиской; **переживает ещё не смонтированный Vue** |
| `ctx.whenVueReady()` | `Promise<vm\|null>` — если нужен стейт прямо сейчас, а не по изменению |
| `ctx.interval(fn, ms)` / `ctx.timeout(fn, ms)` | таймеры с авто-очисткой |
| `ctx.mount(node, parent?)` | вставить свой узел с авто-удалением |
| `ctx.addCleanup(fn)` | произвольная очистка |
| `ctx.isDisposed()` | проверка в асинхронном коде после `await` |
| `ctx.log` | логгер, префиксованный id модуля |
| `ctx.dom`, `ctx.vue`, `ctx.storage` | ядро |

### 2.5 Мост к Vue

```js
var vue = require('core/vue');

vue.waitForVue({ timeout: 30000 })  // Promise<vm|null>, никогда не реджектится
vue.getState()                      // корневой $data или null
vue.get('weather.hour', fallback)   // безопасное чтение по пути
vue.watch('field.location', cb, { deep: true })   // -> функция отписки
vue.watchWhenReady(path, cb, opts)  // то же, но дождётся монтирования Vue
vue.onFieldChange(cb)               // field.map, deep
vue.onLocationChange(cb)            // field.location
vue.onChatMessage(cb)               // колбэк получает ТОЛЬКО новые сообщения
vue.onHistoryChange(cb)             // cat.history (строка, которая растёт)
vue.onHourChange(cb)                // weather.hour
```

Если Vue не смонтировался, всё возвращает `null` / no-op. Модуль просто не заводится,
исключений в консоли не будет.

### 2.6 Сокет — опционально и по умолчанию выключен

`core/socket.js` умеет перехватывать `WebSocket` на URL с `/ws/cw3/socket.io` и разбирать
кадры `42[...]`, включая framed-payload polling'а. Включается галкой в настройках ядра,
ставится только на `document-start`, только читает.

**Ни один модуль не должен на него завязываться, если задачу решает `$watch`.**
Реактивный стейт — основной источник данных.

## 3. Порядок разработки и параллелизация

### Правило изоляции

Модуль = **один файл** в `src/modules/`. Пока разработчик не выходит за пределы своего файла
(и своего файла данных в `src/data/`), merge-конфликтов быть не может: список модулей
собирается автоматически из имён файлов.

Конфликтуют только правки **общих файлов**: `src/core/*`, `SPEC.md`, `README.md`, `build.js`.

### Волна 0 — сделана

Ядро + партия 1. Это фундамент, дальше его правят точечно и по согласованию.

### Волна 1 — можно делать одновременно, по одному разработчику на модуль

Файлы не пересекаются вообще.

| Поток | Модуль | Файлы |
|---|---|---|
| 1 | `cell-coords` | `src/modules/cell-coords.js` |
| 2 | `param-details` | `src/modules/param-details.js` |
| 3 | `skill-values` | `src/modules/skill-values.js` |
| 4 | `copy-id` | `src/modules/copy-id.js` |
| 5 | `pm-ids` | `src/modules/pm-ids.js` — **заблокирован** до появления HAR `/ls` |

### Волна 2 — есть зависимость по порядку

| Поток | Модуль | Зависит от |
|---|---|---|
| 1 | `sound-core` | — |
| 2 | `notify-pm`, `notify-mention`, `notify-action` | **ждут `sound-core`**: три модуля используют один проигрыватель |
| 3 | `mouth-ids` + `src/data/item-names.js` | независим |
| 4 | `mute-game` | независим |

Как избежать блокировки: `sound-core` делается первым и фиксируется его публичный API
(`require('modules/sound-core').play(name, volume)`), после чего три `notify-*` пишутся параллельно.

### Волна 3 — тяжёлые, по одному человеку на модуль

| Модуль | Комментарий |
|---|---|
| `climb-field` | самый объёмный; свой файл + `src/data/`-ничего не нужно |
| `layout` | трогает CSS, который может конфликтовать со `static-background` и `hide-weather` по каскаду — требует ручной проверки в паре с ними |
| `chat-extras` | делается последним, с чек-листом «поле ввода живо» (см. §5) |

### Что конфликтует по файлам

- **`src/core/registry.js`** — правят, только если нужен новый тип поля в `schema`
  или новая возможность `ctx`. Такие правки собираются в одну задачу и делаются отдельно
  от модулей.
- **`src/core/ui.js`** — новый тип контрола в панели. Тоже отдельная задача.
- **`src/core/vue.js`** — новая удобная обёртка (`onXxx`). Добавлять только то, что нужно
  двум и более модулям; иначе `ctx.watch` прямо в модуле.
- **`src/header.txt`** — новые `@match` / `@grant` / `@connect`. Меняется редко и согласованно.
- **`SPEC.md`** — каждый автор модуля дописывает свою строку в таблицу фич; чтобы не биться,
  правки в разные строки таблицы мержатся легко, но не переписывайте соседние секции.

### Каскад CSS между модулями

Все модульные стили вставляются в `<head>` в порядке включения модулей, с одинаковой
специфичностью. Если два модуля правят один узел (`#cages_div` у `always-day` и
`static-background`), выигрывает тот, чей `<style>` ниже. Это нормально для `opacity` vs
`background`, но конфликтные пары надо проверять вручную. Известные пары:

- `always-day` (`opacity`) × `static-background` (`background`) — не конфликтуют, разные свойства;
- `hide-weather` (`#tr_sky display:none`) × `layout` (перестановка строк) — проверять вместе;
- `grid` (`box-shadow` на `td.cage`) × `climb-field` (оверлей на `td.cage`) — договориться:
  `climb-field` красит фон, `grid` — рамку.

## 4. Соглашения

### 4.1 Префиксы

| Что | Префикс | Пример |
|---|---|---|
| id элементов | `cwb-` | `#cwb-root`, `#cwb-clock`, `#cwb-gear` |
| CSS-классы | `cwb-` | `.cwb-modal`, `.cwb-mod-head` |
| id тега `<style>` | `cwb-style-` (ставится автоматически) | `#cwb-style-grid` |
| ключи хранилища | `cwb:` | `cwb:core`, `cwb:mod.grid` |
| CSS-переменные | `--cwb-` | `--cwb-accent` |

Занято соседями, использовать нельзя: `cwa-da-*` и `cwa-*` (досье агентства),
`cws*` / `cws_sett_*` (CW Shed), `uwu*` (UwU), `cwmod*` (CW Mod).

### 4.2 Ключи хранилища

```
cwb:core            { logLevel, gearCorner, gearHidden, hotkey, socketHook }
cwb:mod.<id>        { enabled: boolean, opt: { <ключ настройки>: значение } }
cwb:climbing-maps   { version, current, tabs: [{ name, grid[60] }] }  // поле для ЛУ
cwb:climbing-grid   устаревшая плоская сетка, мигрирует в climbing-maps
```

Значения всегда сериализуются в JSON-строку — так экспорт одинаков для GM-хранилища и
localStorage. В `opt` попадают **только** значения, отличающиеся от `defaults`: сброс к
дефолту = удаление ключа, поэтому изменение `defaults` в коде подхватывается автоматически.

Экспорт/импорт — кнопки в панели, формат:

```json
{ "format": "catwar-balconette-settings", "formatVersion": 1,
  "exportedAt": "...", "data": { "core": {...}, "mod.grid": {...} } }
```

### 4.3 Стиль кода

- ES5-совместимый синтаксис в ядре (`var`, `function`), без транспиляции.
  В модулях допустимы `const`/`let`/стрелки/`async` — Tampermonkey современный,
  но ядро держим максимально консервативным.
- Один модуль = один файл, `module.exports = { … }` в конце.
- Никаких глобалов: всё через `require('core/…')`.
- Комментарии — по-русски, там где логика неочевидна (почему именно такой селектор,
  почему `!important`, чем это ломалось в старых модах). Очевидное не комментируем.
- Все селекторы игры выносим в константы наверху файла модуля, если их больше двух.
- Любая работа с DOM игры — через `dom.qs/qsa/waitForElement`, они не бросают исключений.
- Асинхронный код после `await`/`.then()` обязан проверять `ctx.isDisposed()`.

### 4.4 Пошаговая инструкция: как добавить модуль

1. Придумать `id` в kebab-case. Он же — имя файла: `src/modules/<id>.js`.
2. Скопировать шаблон ниже, заполнить `title`, `description`, `category`, `pages`.
3. Если фича выражается CSS — написать только `styles(settings)`, `init` не нужен.
4. Если нужны данные игры — брать их из `ctx.vue`, не из DOM и не из сокета.
5. Настройки: значения в `defaults`, описание контролов в `schema`.
6. Большие словари данных — в отдельный файл `src/data/<id>.js`.
7. `node build.js` — файл подхватится автоматически, регистрировать нигде не надо.
8. Проверить на `test/mock.html`: включается, выключается, при выключении не остаётся
   ни `<style>`, ни своих узлов, ни ошибок в консоли (уровень логов «Отладка»).
9. Дописать строку в таблицу фич в этом файле.

### 4.5 Шаблон модуля

```js
/**
 * <Название фичи>.
 *
 * Почему именно так: <ссылка на раздел research/NEW_SITE.md или MODS.md,
 * какой узел игры за это отвечает, чем ломались старые моды>.
 */

var dom = require('core/dom');

module.exports = {
  id: 'my-feature',
  title: 'Моя фича',

  category: 'field',

  order: 100,

  defaults: {
    color: '#ffffff',
  },

  schema: [
    { key: 'color', type: 'color', label: 'Цвет' },

  // Чисто визуальная часть.

  init: function (ctx) {
    ctx.dom.waitForElement('#cages').then(function (table) {
      if (!table || ctx.isDisposed()) return;

      ctx.on(table, 'mouseover', function (e) { /* … */ });
      ctx.watch('field.location', function (loc) { /* … */ }, { deep: true });
      ctx.mount(dom.el('div', { id: 'cwb-my-feature' }));
    });
  },

  // Обычно не нужен: ctx снимает всё сам.
  // destroy: function (ctx) {},
};
```
